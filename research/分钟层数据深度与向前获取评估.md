# 分钟层数据深度与"向前获取"可行性评估

日期：2026-09-11
脚本：`scripts/probe_fsdb_minute_history.py`、`scripts/probe_baostock_capability.py`、
`scripts/probe_baostock_vs_fsdb.py`、`scripts/probe_tdx_minute_history.py`

## 一、结论（一句话版）

| 目标 | 能否向前 | 现实路径 |
|---|---|---|
| **1 分钟，2022-2024** | ❌ **不能**（免费渠道无解） | 券商 QMT（免费，可回补多年）或商业源 |
| **5 分钟，2020 年至今** | ✅ 能 | baostock（免费，已实测） |
| 15/30/60 分钟，2020 年至今 | ✅ 能 | baostock（同一接口换 frequency） |

现有分钟湖的真实下界仍是 **2025-01-02**，本次核实**没有变化**。

## 二、现状核实：fsdb 边界仍卡在 2025-01-02

对 `000001` / `600000` 按年拉取（`scripts/probe_fsdb_minute_history.py`）：

```
000001  2018-2024: 0 行
000001  2025:     58,563 行  2025-01-02 → 2025-12-31
000001  2026:     40,478 行  2026-01-05 → 2026-09-10
```

进一步探测表结构：`分钟k`（1 分钟）一周返回 1,205 行，而 `5分钟k`/`15分钟k`/
`30分钟k`/`60分钟k`/`tick` 全部返回 0 —— **镜像里只发了 1 分钟一张表**，
README 宣称的 "1/5/15/30 分钟 + tick" 是引擎能力，不是本镜像的存量。

### 为什么 fsdb 补不到更早

`docs/DATA_SOURCE.md` 写得很清楚：同步器是**镜像清单驱动**
（`manifest.txt` + sha256 校验 + `.ldb` 文件替换），数据深度**完全由镜像发布者决定**，
客户端没有"请求更深历史"的参数。当前 `sync_url.txt` 指向
`https://ah.123128.xyz` / `https://ad.123128.xyz`，直连 manifest 返回 204（按客户端特征放行），
外部无法查看或换源。

→ 除非作者发布更早的历史快照，否则**本地再怎么同步也拿不到 2025 之前的数据**。

## 四、baostock：唯一现成可用的"向前"渠道

### 覆盖边界（实测，非官方口径）

- **起点 = 2020-01**。2019-12 及以前（2015/2017/2018/2019 抽样）全部 0 行。
  官网宣称"5/15/30/60 分钟 1999-07-26 至今"，**实测不符**，以实测为准。
- 市场：沪主板 / 深主板 / 创业板 / 科创板 ✅；**北交所 ❌**（error 10004011）；
  指数部分支持（`sz.399006` ✅、`sh.000300` ✗）。
- 1 分钟：**不支持**，`frequency="1"` 直接报错。

### 与现有 1 分钟湖的重叠期对账（2025-03，4 只 × 10 股日）

两边各自**按日聚合**后比对：

| 字段 | 中位 | p95 | max |
|---|---|---|---|
| open | 0.000% | 0.000% | 0.000% |
| high | 0.000% | 0.097% | 0.099% |
| low | 0.000% | 0.099% | 0.149% |
| close | 0.000% | 0.104% | 0.296% |
| **vol** | **0.790%** | 1.633% | 6.056% |
| amount | 0.790% | 1.629% | 6.085% |

**判读**：价格几乎完全一致（同源行情），成交量系统性偏低 <1%（尾部到 6%）——
与已知口径差一致：fsdb 1 分钟含 15:00 收盘集合竞价 bar，baostock 5 分钟不含。
拼接可用，但**量额字段必须标注口径，不能与 1 分钟段直接拼成一条序列做量相关研究**。

### 拉取速度

- 正常：**约 900-1,800 行/s**（1 个月 5 分钟 ≈ 1s）。
- 偶发限流：某次拉 2024 全年只回 2,000 行、耗时 199s（≈10 行/s），且下一次查询返回 0 行。

按常态速度外推：单股 5 年（≈58,000 行）≈65s → **5,000 只全量回补 ≈ 90 小时串行**。
→ **适合按需取（研究标的池 / 特定时段），不适合无脑全市场回补**。

## 六、建议

1. **要 2020-2024 的 1 分钟**：唯一免费路径是**券商 QMT（miniQMT）**——
   `download_history_data(period='1m')` 可回补多年，还能顺带拿 3 秒快照。
   需开户（门槛各券商不同，普遍 2-10 万资产）。这是把分钟层向前推 5 年的**正解**。
2. **只要日内节奏类研究（5 分钟够）**：接 baostock，作为 `kline_5min` 独立层入湖
   （按 `year=YYYY/part-*.parquet` 分区，与 `kline_1min` 同构），
   注意三点：① 无北交所；② 起点 2020-01；③ 量额口径与 1 分钟段不同，不要混拼。
3. **短期不投入**：若研究主题不依赖长历史日内数据，维持现状（1 分钟 2025 起 + 每日增量自积累）。
4. **待办**：排查通达信通道失效原因（今日仍在降级运行），确认是网络环境变化还是服务器池失效。

## 七、⚠️ 后续更新（2026-09-11 晚）：结论已被推翻

本文第一节"1 分钟 2022-2024 免费无解"的判断，在当日被后续实测**推翻**。

用户购置了 tushare 代理（`https://t.xiaodefa.top/`，限时 token），实测：

- **1 分钟深度回溯到 2005-01-04**，2022-2024 全覆盖（726/726 交易日，零缺失，每日恒 241 根）
- 覆盖沪深主板/创业板/科创板/北交所/ETF；指数走 `idx_mins`
- 全市场 2022-2024 ≈ 8.8 亿行，约 18 小时可跑完
- 与 fsdb 同源（12 只样本 9 只逐根一致），价格同为不复权原始价

因此第一节表格中的"券商 QMT 是唯一正解"应修正为：
**在有该代理可用期间，QMT 不再是必需项**；但代理是限时的，QMT 仍是长期方案。

详细评估、口径比对、混用规则与回填方案见
**`research/tushare代理分钟线回填评估.md`**（含脚本 `scripts/backfill_minute_xiaodefa.py`）。
