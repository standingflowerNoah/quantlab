一、已定架构决策

决策项结论理由
运行形态CodeBuddy 沙箱内运行（系统设计为可整体迁移）数据随沙箱持久保留，agent 每次会话直接读写；纯 Python + 单目录 + DuckDB，随时可整体拷贝到服务器/本地机继续跑
数据存储DuckDB + Parquet 分层数据湖零运维单文件分析型数据库，可直接 SQL 查询 Parquet，全市场 5000+ 股票多因子截面 join 性能强，agent 可直接用 SQL 做研究
数据源策略免费源为主（mootdx/腾讯/东财）+ iFinD 增强免费源跑量、iFinD 补强独有数据（一致预期明细/分钟高频/行业指标），成本最低且互为冗余
执行定位模拟盘起步 + 实盘接口预留本地撮合引擎完整跑通订单→成交→归因闭环；券商接口抽象为 BrokerBase，验证稳定后接入富途/QMT

二、总体架构 System Architecture

五层垂直架构，每层独立可用、逐层依赖；agent 通过 CLI 与 Skills 操作各层，所有中间产物落库落盘，研究过程可追溯、可复现。

Agent 端的含义：系统的"操作员"是 AI agent（你我）。每一层都提供两类入口——CLI 命令（确定性执行，如 ql data update）和 Agent Skill（研究型流程，如因子研究闭环，AI 按 SKILL.md 中定义的标准流程自主调度工具、读写数据库、生成报告）。确定性计算全部下沉到 Python 库，AI 只负责"提出假设、调度流程、解读结果"，避免 LLM 直接算数带来的不可复现问题。

3.2 存储分层设计（DuckDB + Parquet）

data/
├── quant.duckdb              # DuckDB 主库：元数据 + 热数据表 + 全部视图
└── lake/                     # Parquet 数据湖（按域分目录，分区存文件）
    ├── raw/                  # 原始层：接口返回原样落地（可重放，排障用）
    │   ├── kline_daily/date=2026-09-01/
    │   └── dragon_tiger/date=...
    ├── clean/                # 清洗层：标准化 schema、去重、类型修正（研究主入口）
    │   ├── kline_daily/      #   分区：year/ → code 列存
    │   ├── financial/        #   报告期对齐后的财务宽表
    │   ├── fund_flow/  northbound/  margin/  lockup/  hot_topic/ ...
    │   └── instruments/      #   股票主表 + 行业映射
    └── factor/               # 因子层：每个因子每日截面（L2 产出）
        ├── f_mom_20d/
        └── f_...
DuckDB 职责
  • 元数据注册表：数据集清单、更新水位（watermark）、血缘、数据字典
  • 建 Parquet 外表视图：CREATE VIEW kline AS SELECT * FROM read_parquet('lake/clean/kline_daily/**/*.parquet')，SQL 直查湖
  • 热表：交易日历、股票主表、因子注册表、组合状态等小表直接入库
  • agent 研究查询统一入口：一个 .sql 文件或一句 CLI 即可完成跨域 join
数据质量校验（quality.py）
  • 完整性：当日应到数据集的到齐率（如 K线应到 ~5400 只）
  • 新鲜度：水位时间距今延迟（盘后 17:00 后日频数据应到位）
  • 合理性：价格>0、涨跌幅在停牌/涨跌停边界内、量额守恒抽查
  • 一致性：腾讯 vs mootdx 收盘价交叉抽样对比
  • 校验结果写入 quality_report 表，异常项在 agent 会话开始时主动播报

四、L2 因子层 AI 研究闭环 · 因子工程

4.1 AI 因子研究闭环（本系统的灵魂）

① 研究AI 读研报/热点/资金流异常，扫描数据规律
→
② 假设提出可量化假设 → ideas/ 登记（假设/逻辑/预期方向）
→
③ 实现按因子模板写 compute() + 单测 → 一次性跑通
→
④ 分析IC/IR/分层/换手/衰减/相关性 全自动报告
→
⑤ 入库达标→注册版本入库；不达标→归档记录原因

每个 idea 的生命周期状态机：proposed → developing → testing → approved / rejected → decayed，全程留痕在 research/ideas/ 与因子注册表中——保证 AI 的每次"灵感"都可追溯、可复盘、不会重复劳动。

4.2 因子工程管道

环节设计
因子定义每个因子一个 Python 模块，实现统一接口 compute(universe, date) → DataFrame[date, code, value]；声明式元信息（名称/分类/方向/依赖数据域/作者=AI会话ID/版本）
预处理管道可配置组合：缺失处理 → 去极值（MAD/3σ）→ 标准化（z-score/排名）→ 中性化（行业/市值/Barra风格）→ 因子正交化，每步参数存入注册表保证可复现
分析套件RankIC 均值/IR、IC 衰减曲线（1/5/10/20日）、分五组多空净值、换手率、覆盖度、与已入库因子的相关性矩阵（|ρ|>0.7 标记冗余）
入库标准默认门槛（可调）：|RankIC|≥0.02 且 IR≥0.3、分层单调、10日IC半衰、换手可接受、与现有库相关性<0.7
首批因子库动量族（20/60日、剔除近5日反转）、价值族（EP/BP/股息率TTM）、质量族（ROE/盈利增速/应计）、量价族（波动/换手/量价背离）、特色族（主力资金净流入、龙虎榜机构净买、题材热度、北向偏好、融资情绪、解禁压力）——A 股特色数据是相对散户机构的 alpha 富矿

五、L3 模型层 模型设计 · 训练 · 评估

模块设计
样本构建dataset.py：X = 截面因子矩阵（point-in-time 对齐），y = 未来 N 日超额收益（相对中证全指，剔除涨跌停/停牌/ST 不可交易样本）；特征与标签的时间对齐由数据层 watermark 保证
三级火箭① 线性回归/Ridge（基准，可解释，系数即因子权重）② LightGBM（主力，捕捉非线性交互）③ 可选 NN（LSTM/Transformer，仅当前两级显著超额时启用，避免过拟合个人算力）
训练协议walk-forward 滚动训练：训练窗 4 年 → 验证 6 个月 → 滚动前进；每期超参与特征重要性归档；严防泄漏（中性化、行业均值等统计量只用训练窗内数据计算）
评估标准样本外 RankIC、IC 衰减、分组多空年化/夏普/回撤、分年度稳定性、与简单等权因子组合的增量贡献
模型注册模型文件 + 训练快照（数据版本/超参/评估指标）+ 上线状态（shadow/active/retired），L4/L5 只消费注册表中 active 模型

六、L4 优化层 组合优化 · 风险扫描 · 持续监控

模块设计
组合优化输入 = 模型预测分 + 风险模型（对角+行业因子近似协方差）；求解器： scipy 凸优化，约束 = 个股上限（默认2%）、单行业上限（默认15%）、单日换手上限（默认30%）、持仓数量（30~80只可调）；输出 = 目标权重
风险扫描下单前强制闸门：组合历史回撤/VaR(95%)/波动率、个股集中度、行业集中度、beta 暴露、涨跌停/停牌不可成交标记、解禁日历冲突（持仓股未来30日解禁占比>5% 告警）；任何一项超阈值阻断订单并报告
持续监控因子层：入库因子 IC 滚动监测，连续 20 日 IC 衰减>50% 触发降级评审；数据层：新鲜度告警；组合层：实际持仓与目标偏离度、实时净值回撤告警；监控报告每日生成，异常时 agent 主动上报

七、L5 决策层 订单 · 执行 · 归因

盘前15:00后模型出分 → 优化器出目标权重 → 生成差异订单草稿
→
风控闸L4 风险扫描 → 人工确认开关（模拟期默认需确认）
→
拆单执行次日开盘 TWAP 分批 → 模拟撮合（VWAP±滑点）
→
盘中监控成交进度/滑点偏差/异常撤补
→
盘后归因Brinson行业归因+因子贡献+交易成本分析 → 日报
模块设计
模拟撮合引擎以当日分钟K线（mootdx）为成交基础：限价单按可成交判断、市价单按 VWAP + 滑点模型（默认 10bp，按流动性市值分档）成交；费用模型 = 佣金万2.5 + 印花税卖出千1 + 冲击成本；涨跌停/停牌不可成交
订单状态机draft → risk_passed → submitted → partially_filled → filled / cancelled / rejected，全状态落库，成交明细含时间/价格/量/费用
实盘预留BrokerBase 抽象（submit/cancel/query_positions/query_balance/on_fill 回调）；后续按此实现 BrokerFutu（富途OpenAPI）/BrokerQMT（miniQMT），模拟撮合引擎本身就是其中一个 Broker 实现，切换零成本
绩效归因日/周/月绩效报告：Brinson 行业归因、因子暴露与贡献、交易成本归因（滑点损耗 vs 理论执行）、与基准（中证全指/中证500）对比
安全设计：实盘接入前，所有订单默认必须人工确认（订单草稿 → 你回复确认 → 才提交）；资金相关操作留完整审计日志；模拟/实盘用不同的账户配置文件强隔离，杜绝误发。

九、Agent 技能设计 AI 操作手册

技能 = 让 AI 按标准流程自主完成研究型任务的"操作规程"，内部调度 CLI 与 SQL，把自由发挥约束在流程框架内。

技能触发场景AI 自主完成的事
quant-data-ops
数据运维官		"更新数据 / 数据体检 / 补数"判断交易日与数据域缺口 → 调度更新 → 校验质量 → 异常自动重试降级 → 输出运维简报
quant-factor-lab
因子研究员		"研究一个XX因子 / 最近什么数据有alpha / 读研报找灵感"数据扫描/研报阅读 → 登记idea → 写因子代码+单测 → 跑分析 → 达标入库/给出否决理由 → 生成研究备忘录
quant-model-lab
模型工程师		"训练模型 / 评估模型 / 模型为何衰减"组装数据集 → 训练协议执行 → 与基准对比 → 注册/shadow → 输出模型评估报告
quant-portfolio
组合经理		"调仓 / 风险扫描 / 今天组合怎么样"跑优化器 → 风险闸门 → 生成调仓建议单 → 持续监控解读
quant-execution
交易员		"跑今日交易流程 / 出归因日报"盘后流程编排（订单→风控→执行确认→监控）→ 盘后归因日报，实盘模式下严格执行人工确认

十、实施路线图 五个阶段，每阶段可独立验收

阶段内容验收标准
P1 数据层
地基，先跑通		存储引擎 + 股票主表/日历 + 全历史日K + 财务快照 + 特色数据域逐个接入 + 更新调度 + 质量校验 + ql query一键首建全量数据；日常增量自动跑；SQL 能一次查出"全市场最近500日K线+行业+市值"截面
P2 因子层
研究闭环上线		因子引擎+注册表+预处理管道+分析套件+首批 15~20 个因子（含特色数据因子）+ quant-factor-lab 技能AI 能端到端完成一次"研报→假设→因子→分析→入库"闭环并产出报告
P3 模型层数据集构建 + Ridge/LGBM 训练协议 + 评估注册 + quant-model-lab 技能walk-forward 样本外 IC 显著为正且跑赢等权因子组合
P4 优化层优化器 + 风险扫描闸门 + 监控告警 + quant-portfolio 技能给定预测分输出合规目标权重；风险闸门能拦截超限订单
P5 决策层模拟撮合 + 订单状态机 + 拆单 + 归因 + quant-execution 技能模拟盘连续运行：每日自动调仓→成交→归因日报闭环
建议节奏：P1→P2 是价值密度最高的两步（特色数据因子是 A 股 alpha 富矿，且不依赖模型即可做简单多空分层验证）。每个阶段完成后我会停下来给你演示验收，你确认后再进下一阶段。
